## 1. 产品概述

### 1.1 项目背景
经过前期调研和业务调整，我们决定将产品模式从“单次课程拼团”升级为“5节课包拼团”。用户一次性购买5节课的课包，通过拼团方式平摊总价。平台提供固定内容、固定教练、固定地点，由团长选择连续5周的上课时间（仅选择星期和整点，不选具体日期，由平台根据当前周自动计算）。

### 1.2 产品定位
一款面向深圳社区家长的微信小程序，家长可以发起或参与儿童体适能课包（5节课）的拼团。开团时需选择目标人数（如2人、4人、6人、8人），每人立即支付平摊后的金额，达到目标人数即成团，未达成则自动退款。

### 1.3 与原有模式的关系
- 代码层面保留单次课程拼团的数据库表和逻辑，但**前端首页仅展示课程拼团**，单次课程模式暂不开放入口。
- 数据层保留“单次课程模式 + 课包拼团模式”双模式并存，但**家长端只展示课程拼团入口**，**运营后台UI第一版也只开放课包管理入口**。
- 前台面对用户的展示文案统一使用“课程”；后台模块名、接口字段名和数据库表名仍沿用“课包 / package”命名，避免影响现有数据结构与研发实现。
- 后续如需恢复单次课程模式，只需恢复前端Tab和后台菜单入口，无需推翻数据层设计。

## 3. 家长端功能需求

### 3.1 首页 - 课程列表

- **顶部定位栏**：左侧显示当前定位（如“深圳南山区”），点击可重新定位。
- **顶部 Banner 区**：
  - 定位栏下方新增 Banner 轮播区，作为首页首屏主视觉。
  - 当前版本先使用展位图/占位 Banner 展示促销或品牌信息，后续再接入正式 Banner 数据源。
  - Banner 支持自动轮播与指示点展示；第一版以展示为主，跳转能力可后续补充。
- **Tab 切换**：固定为“全部课程 / 体适能 / 跳绳”。
  - “全部课程”：展示全部上架课程
  - “体适能”：仅展示 `package_category=体适能` 的课程
  - “跳绳”：仅展示 `package_category=跳绳` 的课程
- **内容模块结构**：
  - 分类 Tab 与下方课程卡片列表放入同一个统一视觉容器中。
  - 容器使用统一背景、圆角与阴影，强化“筛选条件 + 结果列表”的模块关联感。
  - 内容区主体仍为课程卡片列表，支持无限滚动。
- **排序规则**：
  - 各个 Tab 下统一按“距离优先”排序
  - 先按用户当前定位与课程经纬度的距离从近到远排序
  - 若两个课程距离相同，则按课程上架/创建时间倒序排序，越晚上架的排在越前面
  - 若课程缺少经纬度，则视为距离未知，排在有明确距离的课程之后
- **课程卡片元素**：
  - 封面图
  - 课程名称
  - **价格文案**：显示格式“¥X起”
  - 其中 `X` 取该课程支持团型中的**最低人均售价**
  - 若课程支持多个团型（如2/4/6/8人团），以所有团型售价中的最小值作为首页展示价格，不再展示“X人团人均¥Y”
  - 上课地点（小区+详细地址）
  - 距离标签（如“350m” / “1.2km”）
- **交互**：点击卡片进入课程详情页。
- **可见性规则**：
  - 首页列表中展示的课程，必须保证点击后可正常进入课程详情页，不允许出现“列表可见但详情返回课程不存在”
  - 首页列表与课程详情页使用同一套前台可见性判断口径
  - 若课程 `status = 上架`，但未配置 `publish_time`，前台仍按“已上架可见”处理
  - 仅当课程明确为下架，或 `publish_time` 晚于当前时间且配置合法时，才允许前台判定为不可见
- **视觉约束**：
  - 首页首屏不再展示“邻动体适能”“5次课程拼团”等独立文字介绍模块，顶部空间优先留给 Banner。
  - Tab 选中态需具备明显高亮效果，未选中态弱化处理，但整体风格需与统一内容容器保持一致。
  - 首页课程卡片不展示“X个团进行中”类文案或标签，仅保留封面、名称、地点、距离与价格信息。
  - 列表触底时，底部文案展示为“课程正在逐渐开放中”。

### 3.2 课程详情页

- **顶部轮播图**
- **课程信息**：
  - 课程名称
  - 总价（显示“总价 ¥XXX”）
  - 支持拼团：按后台配置的拼团人数及对应价格展示，如“2人团，每人¥X；4人团，每人¥Y”
  - 不允许前端写死固定团型价格映射；展示内容必须直接来源于后台配置
  - 上课地点（区域、小区、详细地址）
  - 教练姓名、简介、证书
  - 课程介绍（富文本）
  - 保险说明（固定文案）
- **当前进行中的拼团列表**：
  - 每个拼团卡片第一行显示：`X人成团，每人¥Y`
  - 其中：
    - `X` 为该团目标成团人数
    - `Y` 为按该团目标人数计算的人均应付金额
  - **进行中团的上课时间文案仅显示“每周X HH:00，共5次”，不显示具体首课日期**
  - **不展示团长昵称**
  - 卡片右上角继续展示剩余时间
  - 不再单独展示“当前进度 X/Y”
  - 不再单独展示“每人¥Y”辅助文案，避免与标题重复
  - 卡片最后一行左侧展示上课时间文案，右侧展示参团按钮
  - 未满员时按钮文案改为“还缺N人，立即拼”
  - 其中 `N = 目标人数 - 当前已参团人数`
  - 若 `N <= 0`，则该团不应继续出现在“当前进行中的拼团”列表中；若因状态刷新延迟短暂出现，按钮降级为不可点击态“已满员”
- **底部固定栏**：
  - 客服图标（弹出企业微信二维码）
  - 按钮“立即开团”（橙色填充）
- **未登录拦截**：
  - 未登录用户点击“立即开团”或“去参团”时，不直接发起登录，也不跳转“我的”页。
  - 当前页底部拉起与“我的”页共用的登录弹层。
  - 登录弹层拉起时需隐藏原生底部 TabBar；关闭弹层或登录成功后恢复 TabBar。
  - 登录成功后需继续执行用户原本要做的动作：点击“立即开团”则进入开团页，点击“去参团”则进入对应拼团支付确认页。

### 3.3 开团页面

- **页面标题**：显示“开团”
- **课程摘要信息**：
  - 展示课程名称
  - 不展示课程总价
  - 展示上课地点，格式固定为“市 / 区 / 小区”
- **选择拼团人数**：从该课程支持的选项中单选（如2人、4人、6人、8人）
- **选择第一次上课时间**：
  - 提供两个选择器：
    - 星期选择：周一、周二、周三、周四、周五、周六、周日（单选）
    - 上课时间选择：例如 09:00、10:00、11:00、14:00、15:00、16:00、17:00、18:00、19:00（精确到小时，可配置列表）
  - **不选择具体日期**。平台根据当前周自动计算：假设用户选择“周六 10:00”，则系统以开团成功当天所在的周为基准，取下一个最近的周六（如果当天是周六且时间未过则取当天，否则取下周六），作为第一次上课时间，后续自动生成连续5周。
- **孩子信息**：
  - 新增“孩子昵称”输入框
  - 新增“年龄”输入框，仅允许输入数字年龄，且只允许整数岁
- **支付金额展示**：
  - 区块标题改为“支付金额”
  - 金额随当前选择的拼团人数实时联动展示
  - 计算口径：总价 ÷ 当前所选拼团人数，精确到分
  - 不展示“金额按总价平摊后向下取整”类说明文案
- **拼团说明**：
  - 位于协议勾选区域上方
  - 至少包含：满 N 人成团、开团后 48 小时截止、未成团自动退款、成团后锁定首课日期
- **开团成功定义**：
  - 团长点击“确认开团并支付”后，**在开团页直接拉起微信支付**
  - **仅当支付成功后，才真正创建拼团记录**
  - 创建成功后团长自动成为该团第一个已支付成员，`current_count = 1`
- **协议勾选**：
  - 默认勾选《课程服务协议》
  - 不再展示“查看协议全文”独立文案
  - 仅高亮展示“《课程服务协议》”，点击后进入协议详情页
- **按钮“确认开团并支付”**：
  - 点击后在当前开团页直接调用微信支付，支付成功后创建拼团
  - 不再跳转单独的“确认支付”页
  - 按钮宽度需拉伸至与屏幕可用宽度一致

### 3.4 参团页面（从拼团列表进入）

- **页面标题**：显示“参与拼团”
- **课程摘要信息**：
  - 展示课程名称
  - 不展示“订单信息”区块标题
  - 上课地点仅展示“市 / 区 / 小区/场地名称”
  - 删除“开团方式”信息
  - 字段文案“目标人数”改为“该团目标人数”
- **展示拼团信息**：
  - 展示该团目标人数、当前进度、剩余时间
  - 当前进度展示形式与拼团详情页保持一致，包含进度条与 `当前人数 / 目标人数`
  - 展示成员列表，成员信息口径与拼团详情页保持一致
  - 不再单独展示“支付金额”信息区块
- **孩子信息**：
  - 参与现有拼团时，同样需要填写孩子昵称与年龄
  - 年龄仅允许输入数字年龄，且只允许整数岁
- **限制规则**：
  - 同一个课程允许存在多个进行中的团
  - 同一个用户对同一个课程**不允许重复开团或重复参团**
- **协议勾选**：默认勾选《课程服务协议》
- **协议区样式**：
  - 删除独立的 label 行
  - “我已阅读并同意《课程服务协议》”文案上移，与勾选框顶部对齐展示
- **按钮**：
  - 主按钮文案改为“确认支付X元”，其中 `X` 为当前参团应支付金额
  - 点击后支付，支付成功后加入拼团

### 3.5 拼团详情页

- **课程信息摘要**：
  - 进行中：显示“每周X HH:00，共5次，成团后锁定首课日期”
  - 已成团/已失败：显示5次课的具体日期时间（由系统根据团长选择的星期和整点自动生成）
  - 标题展示为“X人成团，每人¥X元”
  - 课程名称、地点
  - 地点仅展示“市 / 区 / 小区/场地名称”
  - 不展示教练信息
- **拼团进度**：进度条、剩余时间
- **成员列表**：
  - 所有已支付成员统一使用默认头像
  - 成员名称展示该成员参加拼团时填写的孩子昵称
  - 无团长标识
- **分摊金额**：显示每人应付金额（按目标人数计算），以及当前已支付成员列表
- **分享**：
  - 拼团详情页支持分享转发给好友
  - 分享落地页仍为当前拼团详情页，接收方可查看详情并在未参团时进入参团流程
- **底部操作**：
  - 进行中且用户已参团：显示“邀请好友”按钮（分享）
  - 进行中且用户未参团：显示“立即参团”按钮（跳转支付）
  - 已成团：显示“已成团，等待上课”
  - 已失败：显示“拼团失败，已退款”

### 3.6 我的拼团列表

- 顶部Tab：全部、进行中、已成团、已失败
- 列表项：课程名称、上课时间（第一次上课时间）、地点、状态、操作（查看详情）
- 不展示“每人¥X元”
- 若状态为进行中，额外展示“还缺X人”标签，其中 `X = 目标人数 - 当前人数`
- 无评价功能。

### 3.7 我的页面

- 用户头像、昵称
- 未登录时展示默认头像卡片与“立即登录”文案
- 点击“立即登录”时，拉起与课程详情页共用的底部登录弹层
- “我的拼团”入口
  - 已登录：进入“我的拼团列表”
  - 未登录：不 toast，不直接登录，拉起共用底部登录弹层
- “用户协议和隐私政策”入口
  - 点击后进入协议列表页
  - 列表页仅展示《用户协议》《隐私政策》两个独立入口
- 联系客服（弹出企业微信二维码）

### 3.8 登录授权与协议

- **首次启动体验**：
  - 用户首次进入小程序时，直接进入首页，不展示强制协议确认页，不阻断浏览课程列表。
- **协议内容来源**：
  - 《用户协议》与《隐私政策》使用 `docs/miniprogram/用户协议.md`、`docs/miniprogram/隐私协议.md` 的正式文案同步到小程序内置富文本。
  - 协议内容页需展示对应的发布日期/生效日期，不再使用占位文案。
- **共用底部登录弹层**：
  - 触发入口：
    - “我的”页点击“立即登录”
    - “我的”页未登录点击“我的拼团”
    - 课程详情页未登录点击“立即开团”或“去参团”
  - 弹层形式：底部半屏弹层，白色大圆角面板，带遮罩。
  - 弹层视觉元素：
    - 右上角关闭图标

## 6. 系统规则

### 6.1 拼团规则
- 团长开团时必须选择目标人数（从课包支持的选项中选择）。
- 开团与参团都必须填写孩子昵称与年龄，年龄仅允许整数岁。
- 课程详情页“支持拼团”展示必须严格按后台配置返回的拼团人数与对应价格渲染，不允许前端使用写死映射关系推导价格。
- 团长点击“确认开团并支付”后在开团页直接拉起支付，**只有支付成功才算开团成功**。
- 开团成功后才真正创建 `package_group` 记录，团长自动成为首个已支付成员，`current_count` 从 `1` 开始。
- 参团时立即支付，支付成功后才计入当前人数。
- 同一个课包允许存在多个进行中的团。
- 同一个用户对同一个课包不允许重复开团或重复参团。
- 截止时间内达到目标人数 → 拼团成功，所有成员获得上课权益。
- 达到目标人数后，拼团状态更新为“已成团”，锁定第一次上课具体日期时间，并停止继续参团。
- 截止时间内未达到目标人数 → 拼团失败，系统自动原路退款给所有已支付成员。
- 拼团成功后不支持个人退款，整团取消需线下人工处理。

### 6.2 上课时间生成规则
- 团长选择星期（如周六）和整点时间（如10:00）。
- 进行中阶段仅展示“每周X HH:00，共5次”，**不展示具体首课日期**。
- 系统以**拼团成功时间**为基准，计算“成功后的第一个所选星期 + 整点”，作为第一次上课的具体日期时间。
- 如果拼团成功当日就是所选星期，但所选整点已过，则顺延到下一个自然周。
- 然后自动生成连续5周的同一星期、同一时间。例如：选择周六10:00，开团成功在周三，则第一次上课为本周六10:00，后续为下周六、下下周六，共5次。

### 6.3 支付金额精度
- 每个团员的**实际支付金额必须完全一致**。
- 计算口径：每人支付金额 = `floor(总价分 / 目标人数)`，前端按两位小数展示。
- 总价分与实际已收金额之间的差额由平台承担，不向任一团员补差。

### 6.4 截止时间规则
- 第一版仅支持固定规则：**开团后48小时截止**。
- 课包创建后无需配置多种截止方式，所有团统一按 `创建成功时间 + 48小时` 计算 `deadline`。

## 8. 验收标准

- 家长端首页仅展示课程，无单次课程；卡片上只显示按最多人数计算的人均价，不显示总价。

- 家长端首页顶部不再展示独立产品介绍文案，定位栏下方直接展示 Banner 轮播区。
- Banner 轮播区已预留正式运营位；当前阶段允许先用展位图/占位图替代真实数据。
- 首页分类 Tab 与课程卡片列表处于同一个统一视觉容器中，具备统一背景和圆角样式。
- 首页首个 Tab 文案为“全部课程”。
- 首页课程卡片不展示“X个团进行中”标签或同类文案。
- 首页列表中任一可点击课程，点击后都应能正常进入课程详情页，不得出现“课程不存在/课包不存在”的前台错误。
- 首次进入小程序直接展示首页，不再强制弹出协议确认页。
- 开团时可选择目标人数、星期和整点时间（无具体日期），支付成功生成拼团，系统自动计算出第一次上课具体时间。
- 开团页顶部仅展示课程名称与“市 / 区 / 小区”格式地点，不展示课程总价。
- 开团页“选择目标人数”文案改为“选择拼团人数”，“整点”文案改为“上课时间”，“支付预估”文案改为“支付金额”。
- 开团页新增孩子昵称与年龄输入框，其中年龄仅允许输入整数岁。
- 开团页在协议区上方展示“拼团说明”。
- 开团页协议区仅高亮展示“《课程服务协议》”并支持点击跳转，不再展示“查看协议全文”独立文案。
- 点击“确认开团并支付”后在开团页直接拉起支付，不再进入单独的确认支付页。
- 课程详情页“支持拼团”按后台配置的拼团人数及价格展示，不允许前端写死团型价格映射。
- 参团确认页同样需要填写孩子昵称与年龄后方可支付。
- 拼团详情页在进行中状态下只展示“市 / 区 / 小区/场地名称”，不展示教练信息。
- 拼团详情页不再单独展示状态标签、“已拼X人”、孩子昵称、孩子年龄等字段；标题统一展示“X人成团，每人¥X元”。
- 成员列表展示参团孩子昵称并统一使用默认头像。
- 我的拼团卡片不展示“每人¥X元”；进行中卡片额外展示“还缺X人”标签。
- 拼团详情页的剩余时间必须严格按“开团成功时间 + 48小时截止”计算并展示。
- 拼团详情页支持分享转发，分享落地后可继续查看当前拼团详情并参与拼团。
- 拼团列表不显示团长昵称。
- 参团时支付成功增加人数，达到目标人数自动成团。
- 同一个用户不能对同一个课包重复开团或重复参团。
- 截止时间未成团，所有成员自动退款。
- 进行中团仅显示“每周X HH:00，共5次”，成团后才展示5次具体上课日期时间。
- 拼团详情页正确显示5次上课时间（具体日期时间）、成员列表、分摊金额。
- 运营后台可正常管理课包、查看订单、手动退款。
- 拼团成功后不支持个人退款。
