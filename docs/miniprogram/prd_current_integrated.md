## 1. 产品概述

### 1.1 项目背景

邻动体适能面向深圳社区家长，提供家门口儿童体适能课程。现阶段产品已从早期“单次课程拼团”升级为“5 节课程拼团”：平台配置固定课程内容、教练、地点与团型价格，家长可发起或参与课程拼团，达到目标人数后成团，未成团自动退款。

### 1.2 产品定位

一款面向深圳社区家长的微信小程序。家长可浏览附近课程、查看课程详情、发起拼团、参与拼团、支付课程费用、查看拼团详情与个人拼团记录。

### 1.3 当前业务模式

- 家长端只展示课程拼团入口，前台文案统一使用“课程”。
- 后台和数据层保留“课包 / package”命名，以兼容当前表结构与接口。
- 数据层保留早期单次课程拼团表和逻辑，但家长端首页不再开放单次课程入口。
- 课程拼团默认以 5 节连续课程为售卖单元。
- 开团时选择目标人数、星期和整点时间，不选择具体日期。
- 成团后系统根据成团时间、所选星期和整点自动锁定首课日期，并生成连续 5 周课程安排。

## 2. 用户与目标

### 2.1 目标用户

- 深圳社区内 3-12 岁儿童家长。
- 关注便利性、价格透明度、教练专业性与上课安全。
- 对“家门口上课”和“拼团降低人均价格”有明确需求。

### 2.2 核心目标

- 跑通“后台配置课程 -> 家长浏览课程 -> 开团/参团 -> 支付 -> 成团/失败退款 -> 我的拼团”的主链路。
- 降低家长决策成本，突出地点、价格、团型、进度和退款规则。
- 保留后续恢复单次课程模式的扩展空间，但当前不作为前台主入口。

## 3. 全局规则

### 3.1 登录与协议

- 首次进入小程序直接展示首页，不再强制展示协议确认页。
- 用户可在未登录状态浏览首页与课程详情。
- 未登录用户点击“立即开团”“去参团”或“我的拼团”时，拉起共用底部登录弹层。
- 登录方式为微信一键登录，仅调用 `wx.login` 获取 code 后向后端换取 token。
- 不采集微信头像昵称，不调用 `wx.getUserProfile`，不申请手机号授权。
- 登录弹层内展示协议勾选区，协议默认不勾选。
- 未勾选协议点击登录时，提示“请先阅读并勾选用户协议”。
- 登录成功后关闭弹层，并继续执行用户原本动作。
- 弹层打开时隐藏原生 TabBar，关闭或登录成功后恢复 TabBar。
- 《用户协议》《隐私政策》《课程服务协议》使用小程序内置正式富文本内容。

### 3.2 金额展示

- 金额统一按“去尾零”规则展示。
- 若小数点后两位均为 `0`，展示整数，如 `99.00` 展示为 `99`。
- 若小数点后非全 `0`，保留两位小数，如 `99.50`、`99.99`。
- 首页、课程详情、开团页、参团页、拼团详情页均使用同一展示规则。
- 实际支付金额以后台团型售价配置为准；若历史数据缺失配置，才允许回退为 `总价 / 目标人数`。

### 3.3 地点展示

- 前台课程地点不展示省级信息。
- 首页卡片展示“小区 + 详细地址”。
- 课程详情、开团页、参团页、拼团详情页可展示“市 / 区 / 小区 / 场地名称或详细地址”。
- 市、区字段可用于定位、距离排序和后台管理，但不应在首页卡片主文案中展示省。

### 3.4 拼团规则

- 同一个课程允许存在多个进行中的团。
- 同一个用户可对同一课程多次开团或参团，用于为多个孩子报名。
- 同一个用户可对同一个拼团多次报名，每笔支付成功订单占用 1 个拼团名额。
- 每笔订单对应 1 个孩子，订单上下文记录该孩子的昵称、年龄和家长手机号。
- 同一用户同一课程仅保留 1 笔待支付订单；创建新待支付订单时，系统关闭旧待支付订单，避免重复未支付订单堆积。
- 开团和参团都必须填写孩子昵称、年龄和家长手机号。
- 年龄仅允许整数岁。
- 家长手机号仅允许输入中国大陆 11 位手机号。
- 开团成功定义为团长成功支付后创建拼团记录。
- 未支付不算参团成功，不增加拼团人数，不进入“我的拼团”。
- 开团成功后团长成为第一个已支付成员，`current_count = 1`。
- 参团支付成功后 `current_count + 1`，人数统计按已支付订单名额计算，不按用户去重。
- 达到目标人数后，拼团状态变为已成团，并锁定首课日期。
- 截止时间内未达到目标人数，拼团失败，系统自动原路退款。
- 拼团成功后不支持个人线上退款，整团取消需线下人工处理。

### 3.5 截止时间

- 拼团截止时间按后台配置 `deadline_hours` 计算。
- 计算口径为：`开团支付成功创建团时间 + deadline_hours`。
- 前端不自行推导截止时间，只消费后端返回的 `remaining_seconds / remaining_text / deadline`。

### 3.6 微信支付规则

- 生产环境必须接入真实微信支付，支付提供方配置为 `wechat`。
- 开发和自动化测试环境可保留 `mock` 支付能力，用于低成本回归验证。
- 生产环境不允许小程序端在微信支付参数缺失或预下单失败时自动 fallback 到 `mock-success`。
- 本期只接入微信支付收款链路，不接入微信退款 API。
- 自动退款、人工退款本期继续沿用现有订单状态与 `payment_records` 状态同步；后续再扩展微信退款 API 原路退款。
- 支付主链路为：创建待支付订单 -> 后端调用微信支付 JSAPI 下单 -> 小程序调用 `wx.requestPayment` -> 后端接收微信支付通知 -> 后端更新订单、支付记录和拼团状态。
- 小程序 `wx.requestPayment` 返回成功后，前端不得单方面认定订单成功，必须通过后端支付状态确认或等待后端微信支付回调落库。
- 微信支付通知处理必须幂等，同一订单或同一商户订单号重复通知不得重复增加拼团人数。
- 课包拼团订单支付成功后必须走课包拼团成功逻辑：开团订单支付成功后创建拼团并写入团长名额；参团订单支付成功后写入参团名额并更新拼团人数。
- 用户主动取消支付后，后端关闭该待支付订单，订单状态变为 `closed`，不创建拼团、不增加拼团人数、不进入拼团成员列表。
- 真实支付状态以商户后端订单状态为最终依据。若前端查询时仍为处理中，可提示用户稍后查看，不应重复创建新订单。

## 4. 页面需求

### 4.1 首页

- 顶部展示定位栏，点击可重新定位。
- 定位栏下方展示 Banner 轮播区。
- Banner 默认读取首页配置接口，不再以前端写死占位作为主数据源。
- 首页首屏不再展示“邻动体适能”“5 次课程拼团”等独立介绍模块。
- Tab 固定为“全部课程 / 体适能 / 跳绳”。
- Tab 与课程卡片列表放入统一视觉容器。
- 列表按距离优先排序；距离相同按创建或上架时间倒序。
- 无经纬度课程排在有明确距离课程之后。

Banner 规则：

- 首页读取 Banner 配置接口，展示当前城市命中的 Banner 列表。
- 每条 Banner 配置字段包括：图片、跳转类型、跳转目标、排序、上下线时间、适用城市、启用状态。
- 跳转类型当前支持：`none`、`packageDetail`、`customUrl`、`miniprogramPage`。
- `packageDetail` 跳转目标为课程 ID；`customUrl` 为 H5 链接；`miniprogramPage` 为小程序站内页面路径。
- Banner 可见性同时受启用状态、上下线时间、适用城市命中三类条件控制。
- 城市命中优先使用当前选中定位城市；若拿不到城市，仅展示“全国”或未限制城市的 Banner。
- Banner 按排序值升序展示；排序相同按配置顺序兜底。
- 接口失败、超时、返回空列表或无可用 Banner 时，首页展示本地默认 Banner，不阻塞首页上线。
- 本地默认 Banner 仅作为兜底展示，不参与后台运营配置。

课程卡片展示：

- 封面图。
- 课程名称。
- 上课地点，小区 + 详细地址，不展示省。
- 距离标签，如 `350m` / `1.2km`。
- 价格文案：`¥X起`，`X` 取支持团型中的最低人均售价。
- “起”字比主价格数字小 `4rpx`。
- 不展示“X 个团进行中”。
- 不展示总价。
- 点击进入课程详情页。

可见性：

- 首页列表与课程详情使用同一套可见性规则。
- 课程 `status = active` 或已上架可见时，首页才展示。
- 未配置 `publish_time` 的上架课程按可见处理。
- 明确下架或合法未来上架时间未到时，不在首页展示。

### 4.2 课程详情页

展示内容：

- 顶部轮播图，当前可由封面图兜底。
- 课程名称。
- 支持拼团：按后台配置展示，如 `2人团，每人¥X；4人团，每人¥Y`。
- 上课地点，不展示省。
- 教练姓名、简介、证书。
- 课程介绍富文本。
- 保险说明。

当前进行中的拼团：

- 标题行展示 `X人成团，每人¥Y`。
- `Y` 使用统一金额展示规则。
- 不展示团长昵称。
- 不单独展示“当前进度 X/Y”。
- 不单独展示“每人¥Y”辅助行。
- 右上角展示剩余时间。
- 底部左侧展示 `每周X HH:00，共5次`。
- 底部右侧按钮展示 `还缺N人，立即拼`。
- 底部上课时间文案与按钮底部对齐。
- 按钮右侧与上方剩余时间标签右侧对齐。
- 若 `N <= 0`，该团不应继续出现在进行中列表；若短暂出现，按钮降级为不可点击“已满员”。

底部固定栏：

- 客服入口，点击弹出企业微信二维码或客服提示。
- 主按钮“立即开团”。

未登录拦截：

- 点击“立即开团”或参团按钮时未登录，当前页拉起登录弹层。
- 登录成功后继续进入开团页或参团页。

### 4.3 开团页

页面标题为“开团”。

课程摘要：

- 展示课程名称。
- 展示地点，格式为“市 / 区 / 小区”，不展示省。
- 不展示课程总价。

表单：

- 选择拼团人数，从后台支持团型中单选。
- 选择每周上课时间：星期 + 整点。
- 不选择具体日期。
- 填写孩子昵称。
- 填写年龄，整数岁，数字键盘带确认操作。
- 在孩子年龄下方填写家长手机号，使用数字键盘，限制 11 位。

支付与说明：

- 页面中部不再单独展示“支付金额”区块。
- 不展示“每人 XX 元”说明。
- 拼团说明展示满 N 人成团、开团后截止、未成团自动退款、成团后锁定首课日期。
- 默认勾选《课程服务协议》。
- 协议文案与勾选框同一行视觉齐平。
- 主按钮文案为 `支付X元并开团`。
- 点击后在当前页面直接拉起支付。
- 支付成功后创建拼团并进入支付结果页。

### 4.4 参团页

页面标题为“参与拼团”。

展示内容：

- 课程名称。
- 上课地点，不展示省。
- 该团目标人数。
- 当前进度，包含进度条与 `当前人数 / 目标人数`。
- 剩余时间。
- 成员列表。
- 不展示“订单信息”区块标题。
- 不展示“开团方式”。
- 不单独展示“支付金额”区块。

成员列表：

- 所有成员统一默认头像。
- 成员名展示参加拼团时填写的孩子昵称。
- 不展示“微信用户”作为固定前台文案。

表单与支付：

- 填写孩子昵称。
- 填写年龄，整数岁，数字键盘带确认操作。
- 在孩子年龄下方填写家长手机号，使用数字键盘，限制 11 位。
- 默认勾选《课程服务协议》。
- 协议区删除独立 label 行，文案与勾选框顶部/视觉齐平。
- 主按钮文案为 `确认支付X元`。
- 支付成功后加入该团并进入支付结果页。

### 4.5 支付结果页

- 支付处理中：提示正在确认支付结果，并自动查询后端订单状态。
- 支付成功：以后端确认订单 `success` 为准，提示订单已提交，可查看拼团详情。
- 若本次为开团成功或参团支付成功，支付结果页需展示订阅微信通知引导，提示用户订阅后可接收拼团成功或拼团失败通知。
- 订阅引导仅在支付成功状态下展示，支付失败、支付处理中、用户取消支付时不展示。
- 订阅行为不影响支付主流程；用户拒绝订阅、关闭订阅弹窗或订阅失败时，页面仍可正常查看拼团详情。
- 支付失败：提示本次支付未完成，可重新支付或返回首页。
- 用户取消支付：提示已取消支付，该订单已关闭，可重新发起支付。
- 支付成功后可进入拼团详情页。
- 支付失败后可重新支付或返回首页。

### 4.6 拼团详情页

课程信息摘要：

- 页面主标题为课程名称。
- 课程名称下方以标签展示 `X人成团，每人¥Y`。
- `Y` 使用统一金额展示规则。
- 进行中：展示 `每周X HH:00，共5次，成团后锁定首课日期`。
- 已成团/已失败：展示 5 次具体课时安排。
- 地点展示“市 / 区 / 小区 / 场地名称”，不展示省。
- 不展示教练信息。

拼团进度：

- 展示当前人数 / 目标人数。
- 展示进度条。
- 进行中展示剩余时间。
- 非进行中展示终态文案。

成员列表：

- 已支付成员统一使用默认头像。
- 成员名称展示孩子昵称。
- 无团长标识。

底部操作：

- 进行中且用户已参团：显示“邀请好友”。
- 进行中且用户未参团：显示“立即参团”。
- 已成团：显示“已成团，等待上课”。
- 已失败：显示“拼团失败，已退款”。

分享：

- 支持转发给好友。
- 分享落地页为当前拼团详情页。
- 未参团用户可从详情页进入参团流程。

### 4.7 我的拼团列表

- 顶部 Tab：全部、进行中、已成团、已失败。
- 列表项展示课程名称、上课时间、地点、状态。
- 不展示“每人¥X元”。
- 进行中拼团额外展示 `还缺X人` 标签。
- 点击进入拼团详情页。
- 无评价功能。

### 4.8 我的页

- 已登录展示默认头像与昵称。
- 未登录展示默认头像卡片与“立即登录”文案。
- 点击“立即登录”拉起共用登录弹层。
- “我的拼团”入口：已登录进入列表，未登录拉起登录弹层。
- “用户协议和隐私政策”入口：进入协议列表页。
- 联系客服：弹出企业微信二维码或客服提示。

## 5. 数据模型与字段映射

### 5.1 数据模型策略

- 单次课程模式保留原有 `courses / groups / orders(order_type=1)`。
- 课程拼团模式使用 `course_packages / package_groups / orders(order_type=2)`。
- 家长端当前只展示课程拼团。
- 后台当前主流程只开放课包管理、课包拼团和课包订单。

## 6. 通知与退款

### 6.1 订阅通知范围

- 当前支付成功页可发起拼团结果通知订阅授权。
- 用户开团成功或参团支付成功后，支付结果页需引导用户订阅微信通知，以便接收后续拼团成功或拼团失败通知。
- 订阅引导只在支付成功页展示，且仅针对已成功创建或加入拼团的订单。
- 本期仅保留两类微信订阅通知：拼团成功通知、拼团失败通知。
- 不再单独发送“首课时间确认通知”；拼团成功时即自动确认首课时间，并在拼团成功通知内直接带出首课时间和上课地点。

### 6.2 模板与模板 ID

- 拼团成功通知使用模板 `拼团成功提醒`，模板 ID：`S6VR9rfzWPlpFRfZLNpjJzxEyPHEGQDd7KQ-TOHduxc`。
- 拼团失败通知使用模板 `拼团失败通知`，模板 ID：`aXcNy9Dg_lyqbI2RAbpPvRao7reiH2wVBa1WsFi5dp4`。

### 6.3 触发时机

- 拼团成功通知：拼团人数达到目标人数后，后端将拼团状态更新为“已成团”，并同步确认首课时间与地点后立即发送。
- 拼团失败通知：拼团截止时间到达后，人数未达到目标人数，后端将拼团状态更新为“已失败”后立即发送。

### 6.4 字段规则与文案口径

- 拼团成功和拼团失败通知中的 `拼团课程` 字段，统一拼接为 `课程名称(X人团)`，例如 `少儿体适能基础课(4人团)`。
- 拼团成功通知需直接带出 `上课时间` 和 `上课地点`，不得再显示“待确认”。
- 拼团成功通知温馨提示固定为：`拼团已成功，客服稍后将拉您进去课程微信群，请留意后续通知`。
- 拼团失败通知温馨提示需明确表达自动原路退款，例如：`本次拼团未成功，系统将自动原路退款，请留意微信支付到账通知`。

拼团成功通知示例：

```text
拼团课程：少儿体适能基础课(4人团)
上课时间：2026年4月27日 10:00
上课地点：浦东新区 XX 运动中心
温馨提示：拼团已成功，客服稍后将拉您进去课程微信群，请留意后续通知
```

拼团失败通知示例：

```text
拼团课程：少儿体适能基础课(4人团)
失败原因：拼团截止前未达到成团人数
温馨提示：本次拼团未成功，系统将自动原路退款，请留意微信支付到账通知
```

### 6.5 发送规则

- 拼团成功通知：同一用户针对同一拼团最多发送一次。
- 拼团失败通知：同一用户针对同一拼团最多发送一次。
- 同一拼团最终只能进入成功或失败其一，禁止双发。
- 若用户未订阅，不补发站外通知，但站内状态仍需可查询。

### 6.6 退款规则

- 拼团失败后系统自动原路退款。
- 自动退款需更新订单退款状态、退款时间与退款原因。
- 本期微信支付真实接入只覆盖收款，不调用微信退款 API；退款对账和原路退款能力作为后续支付二期补充。
- 失败团历史成员记录保留，用于追溯。

## 7. 非功能需求

- 首页和详情页接口需保证课程可见性一致。
- 列表加载支持分页或滚动加载。
- 支付、登录、退款接口需具备幂等能力。
- 所有金额以分为后端存储单位，前端转元展示。
- 图片资源使用安全可访问 URL，私有桶资源需签名或代理。

## 8. 验收标准

- 未登录用户可浏览首页和课程详情。
- 未登录用户点击开团、参团、我的拼团时正确拉起登录弹层。
- 首页只展示当前可见课程，且点击后能进入详情。
- 首页价格展示为 `¥X起`，金额去尾零，“起”字缩小。
- 首页地点不展示省。
- 课程详情按后台团型售价展示，不写死团型。
- 开团页可选择人数、星期、整点，填写孩子信息并支付开团。
- 参团页可填写孩子信息并支付参团。
- 生产环境点击开团/参团支付必须拉起微信支付，不允许落入模拟支付成功。
- 用户取消微信支付后订单关闭，且不会创建拼团或写入拼团成员。
- 微信支付成功后需以后端支付通知或状态查询确认为准，再展示支付成功结果。
- 微信支付重复通知不会导致订单重复入团或拼团人数重复增加。
- 拼团详情标题为课程标题，下方标签展示 `X人成团，每人¥Y`。
- 成员列表展示孩子昵称。
- 进行中团倒计时以后端返回为准。
- 我的拼团进行中卡片展示 `还缺X人`。
- 拼团失败后订单自动退款，用户可在拼团详情和我的拼团看到失败状态。
