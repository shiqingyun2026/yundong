# 课包多地点支持设计

## 背景

当前正式链路以课包为核心：运营后台配置 `course_packages`，小程序首页、课包详情、开团、参团、订单和拼团管理均走 package 相关接口。现有 `course_packages` 只有一套地点字段，导致同一个课程内容只要服务小区不同，就需要重复创建多个课包。

本次目标是让一个课包支持多个服务地点，同时保持价格、课时、排课规则和教练安排仍然属于课包维度。教练不是事先确定，而是在成团或运营阶段再安排。

## 目标

- 运营后台创建或编辑课包时，可以配置多个地点。
- 小程序首页一个课包只展示一次，距离按该课包离用户最近的地点计算，首页不展示具体小区名。
- 小程序课包详情页展示该课包支持的小区/场地列表。
- 小程序开团页选择要去的地点。
- 小程序详情页活跃团列表展示所有地点的团，并在团卡片展示团地点。
- 活跃团排序按团地点距离优先，距离相同或无定位时按截止时间优先。
- 团创建后锁定地点，后续课包地点编辑不影响已开团记录。
- Console 拼团和订单管理可以看到团地点，方便运营和客服处理。
- 兼容已有单地点课包和历史团。

## 非目标

- 不支持不同地点配置不同价格。
- 不支持不同地点配置不同课时、不同可选人数或不同排课规则。
- 不支持提前绑定某个地点的固定教练。
- 不在第一版做地点维度库存、容量、开团上限或统计报表。
- 不改变已有支付、退款、拼团状态和课包生命周期规则。

## 推荐方案

采用“课包地点表 + 团地点快照”的方案。

课包新增独立地点表 `course_package_locations`。每个课包可以有多个地点，每个地点包含区域、小区/场地名、详细地址、经纬度、排序和启用状态。

用户开团时选择一个启用地点。支付成功并创建 `package_groups` 时，将地点 ID 和地点快照写入团记录。后续团列表、团详情、我的拼团、订单和后台管理展示团地点时，优先使用团上的快照，避免运营后台后续修改地点影响已开团数据。

## 数据模型

### `course_package_locations`

新增表，用于保存课包可选地点。

建议字段：

- `id`: 地点 ID，主键。
- `package_id`: 课包 ID，关联 `course_packages.id`。
- `location_district`: 省 / 市 / 区路径，沿用现有格式。
- `location_community`: 小区或场地名称。
- `location_detail`: 详细地址。
- `longitude`: 经度，可为空。
- `latitude`: 纬度，可为空。
- `sort_order`: 排序值，越小越靠前。
- `status`: 地点状态，`1` 启用，`0` 停用。
- `created_at`, `updated_at`: 时间戳。

索引建议：

- `idx_course_package_locations_package_id(package_id)`
- `idx_course_package_locations_status(status)`
- `idx_course_package_locations_package_status(package_id, status)`

### `package_groups`

新增地点锁定字段。

建议字段：

- `location_id`: 开团时选择的 `course_package_locations.id`，历史团可为空。
- `location_snapshot`: JSON，保存开团时地点快照。

快照建议结构：

```json
{
  "id": "location_xxx",
  "location_district": "广东省 / 深圳市 / 南山区",
  "location_community": "某某小区",
  "location_detail": "某某地址",
  "longitude": 113.0,
  "latitude": 22.0
}
```

### `orders.package_context`

开团订单和参团订单可以额外保存地点快照，作为订单视角的冗余快照。核心事实仍以 `package_groups.location_snapshot` 为准。对于支付成功前的开团订单，`package_context` 应保存用户选择的 `location_id` 和地点快照，便于支付回调创建团。

## 兼容迁移

现有 `course_packages` 上的单地点字段迁移为每个课包的默认地点。

迁移规则：

- 为每个已有课包创建一条 `course_package_locations` 记录。
- 字段来源为 `course_packages.location_district`、`location_community`、`location_detail`、`longitude`、`latitude`。
- `sort_order = 0`，`status = 1`。
- 保留 `course_packages` 原地点字段作为短期兼容字段，不在第一版立即删除。
- 历史 `package_groups` 没有 `location_id` 或 `location_snapshot` 时，展示 fallback 到课包原地点或课包默认地点。

## Console 设计

### 课包表单

原单地点输入改为地点列表。

每个地点项包含：

- 省 / 市 / 区。
- 小区 / 场地名称。
- 详细地点。
- 经纬度。
- 根据详细地点解析坐标。
- 启用状态。
- 上移 / 下移 / 删除。

规则：

- 新建和保存课包时至少保留 1 个启用地点。
- 地点名称、详细地点为必填。
- 经纬度建议通过现有腾讯地图联想和解析能力填入，但允许后台手动保存无经纬度地点。
- 复制课包时复制地点列表。
- 编辑已有课包时，已被团使用的地点不建议硬删除；第一版可以限制删除，改为停用。停用地点不再出现在小程序开团可选地点中，但历史团继续显示快照。

### Console 拼团和订单

拼团列表、拼团详情、订单列表、订单详情展示团地点。

展示优先级：

1. `package_groups.location_snapshot`
2. 关联地点表记录
3. 课包默认地点或旧单地点字段

## 小程序设计

### 首页课包列表

一个课包只展示一次。

有用户定位时：

- 后端对每个课包的启用地点计算距离。
- 取最近地点作为该课包的 `nearest_location`。
- 首页展示该最近地点对应距离。
- 首页不展示小区或场地名。
- 排序沿用距离优先，其后按当前规则处理价格和创建时间。

无用户定位时：

- 不展示距离。
- 按现有默认排序处理。

### 课包详情页

详情页请求课包详情时应带上当前定位经纬度；如果用户没有授权定位，则不传经纬度。详情接口返回启用地点列表。

页面展示“支持小区/场地”：

- 地点列表显示小区 / 场地名。
- 可附带区名或简短区域信息。
- 详细地址可以在展开状态或开团页展示，避免详情页过重。

详情页活跃团列表展示所有地点的团。

排序规则：

1. 有用户定位且团地点有经纬度时，按团地点距离从近到远。
2. 距离相同或无法区分时，按截止时间从近到远。
3. 无用户定位时，按截止时间从近到远。

团卡片展示团地点，建议显示小区 / 场地名，必要时附带区名。

### 开团页

开团页加载课包详情时获取地点列表。

规则：

- 只有一个启用地点时默认选中。
- 多个启用地点时要求用户选择地点。
- 选择项展示小区 / 场地名、区名、详细地址和距离。
- 提交开团订单时传 `location_id`。
- 后端校验地点属于该课包且处于启用状态。

### 参团和支付确认

加入已有团时不允许选择地点。

参团支付确认页和团详情页展示团锁定地点。参团订单继承该团地点快照。

## API 设计

### Console API

`GET /packages/:id`

- 返回 `locations` 数组。
- 为兼容现有前端，短期保留旧单地点字段。

`POST /packages` 和 `PUT /packages/:id`

- 接收 `locations` 数组。
- 校验至少 1 个启用地点。
- 写入课包主表和地点表。
- 修改地点时保护已被团引用的地点，优先停用而不是硬删除。

### Mini Program API

`GET /api/packages`

- 基于地点表计算每个课包最近地点距离。
- 返回 `distance_meters`。
- 可返回 `nearest_location_id` 供调试或后续扩展，但首页不展示小区名。

`GET /api/packages/:id`

- 返回 `locations`。
- 返回 `active_groups`，每个团包含地点快照、地点展示文本和距离。
- 接收可选 `lat` / `lng` 查询参数，用于计算活跃团地点距离和排序。
- 后端按确认的团排序规则排序。

`POST /api/package-orders/start`

- 新增请求字段 `locationId` 或 `location_id`。
- 校验地点属于课包且启用。
- 将地点信息写入开团订单 `package_context`。
- 支付成功创建团时写入 `package_groups.location_id` 和 `location_snapshot`。

`POST /api/package-orders/join`

- 不接收地点选择。
- 从 `package_groups` 读取团地点快照，写入参团订单上下文。

## 业务规则

- 课包地点只影响服务地点，不影响价格、课时、排课规则、成团规则和教练安排。
- 团一旦创建，地点不可变更。
- 已有团引用的地点不能被硬删除；如需不再开放新团，应停用地点。
- 停用地点不出现在小程序开团地点列表中，但历史团、订单、后台查询仍可展示。
- 如果地点缺少经纬度，则无法参与距离精确排序；排序时归为距离未知，排在有距离的团之后，再按截止时间排序。
- 如果用户没有定位，首页不展示距离，详情团列表按截止时间排序。

## 验证计划

后端：

- 地点表 repository 单元测试或 service 测试：创建、更新、停用、查询启用地点。
- 课包列表测试：多地点课包按最近地点计算距离。
- 课包详情测试：返回地点列表，活跃团包含地点并按距离和截止时间排序。
- 开团订单测试：缺少地点、多地点无效地点、停用地点、正常地点。
- 支付成功创建团测试：团保存地点 ID 和快照。
- 参团订单测试：继承团地点，不能覆盖地点。
- 历史数据兼容测试：无 `location_snapshot` 的团 fallback 到课包地点。

Console：

- `npm run lint`
- `npm run build:cloudbase`
- 手动验证新建、编辑、复制课包地点列表。
- 手动验证拼团列表、拼团详情、订单列表可看到地点。

小程序：

- 开团页单地点默认选中。
- 开团页多地点必须选择。
- 详情页支持地点展示。
- 详情页团卡片地点展示和排序。
- 首页距离展示不出现小区名。

回归：

- 需要更新或新增 Playwright regression seed，使测试课包包含多个地点和不同地点的团。
- 重点覆盖首页、详情、开团、参团、后台拼团管理。

## 风险与注意事项

- 该功能涉及数据库、Console、Mini Program API、小程序页面和订单/拼团链路，属于跨模块改造，应分阶段提交和验证。
- 支付成功创建团时必须使用订单上下文中的地点快照，不能重新从课包当前地点推断，避免运营编辑地点造成竞态。
- 首页和详情排序依赖经纬度；后台保存地点时需要尽量引导解析坐标。
- 短期保留 `course_packages` 原地点字段可以降低兼容风险，但后续应另起清理任务评估是否删除或停止使用。
